# Phase 06 RTC architecture

2026-09-11. Phase 06 only. The owner revised quality enforcement and revocation acceptance during this completion pass; see Umbrella §31A.3 and the active Phase 06 specification. Phase 07 is not authorized.

## Boundaries and deployment

`@study/rtc` owns media sessions and registered HTTPS join/audience/renew/leave operations. `@study/feature-sdk` owns `RealtimeMediaProvider`, `MediaAuthority`, tracks, receive surfaces and profile models. Only `@study/adapters/livekit/browser` imports the client SDK, and only its server counterpart holds the signing/admin SDK. Room composition supplies the generic provider to dock, device/menu, badge, audio and workspace contributions. RoomShell imports neither LiveKit nor the RTC feature. Text chat stays on the authenticated application WebSocket/HTTPS control plane; no RTCDataChannel chat or data publication grant is introduced.

Pinned versions: LiveKit server **v1.13.6**, image digest `sha256:e37d68f172556d02aa77968b9fc55ef481468c0315fa38e4fa6c56ce72e3a815`; client SDK **2.22.3**; server SDK **2.19.0**. WebRTC uses ordinary encrypted DTLS/SRTP and SFU forwarding, with no custom crypto, decoding/compositing service or mesh.

`npm run dev` generates random API key/secret into the existing protected `.local/compose.env`, and writes `.local/livekit.yaml`. Existing OAuth/database credentials are preserved. POSIX files use 0600 inside a 0700 directory. On Windows the script verifies or sets the exact protected current-user/SYSTEM/Administrators ACL; it does not bypass an insecure ACL when setting it fails. PowerShell 7 is preferred when available because this workstation's legacy PowerShell cannot reliably load its security module. Neither generated file is committed or supplied to the web build.

The existing Compose topology includes LiveKit. Development restarts apply generated provider configuration before application startup. All exposed ports bind loopback: 7880 HTTP/admin for the host test runner, 7881 ICE/TCP, 7882 ICE/UDP, and 3478 authenticated embedded TURN/UDP. Metrics port 6789 remains container-internal. Caddy exposes only `/rtc` and `/rtc/*` over the existing `wss://localhost:8443` origin. Provider admin `/twirp` endpoints are not proxied. Signaling uses the existing same-origin CSP; no wildcard/external connect origin is added. The API uses private `http://livekit:7880` for server operations. The SFU has an HTTP healthcheck; API readiness includes SFU reachability when enabled; startup verifies authenticated server access through namespace reset.

The local TURN relay plus advertised internal container candidate is necessary on this Docker Desktop host: a browser's non-loopback ICE interface cannot establish a working pair with the SFU's loopback-only candidate. The relay fixes this without browser security flags or publicly exposing a port. This is not production TURN/NAT provisioning. Internet deployment still needs a real hostname/certificate, reachable advertised addresses, UDP/TCP firewall and NAT validation, secure TURN/TLS capacity and testing from independent networks. Same-machine evidence does not establish those properties.

## Credential authorization and capabilities

Join accepts exactly `{roomId}`. The established authentication, CSRF, Origin, strict schema, rate, permission and feature-flag pipeline runs first. `rtc.member` rechecks the current server session, identity, absolute/idle expiry, revocation, current Rooms role and owner-block/access policy. Checks run both before and after asynchronous signing. Client-supplied user, owner, moderator, source permissions, SFU room names and quality fields are rejected. `RTC_ENABLED=false` denies operations at the shared server flag boundary; standalone API composition defaults off, while the configured local Compose deployment defaults on. Disabling admission retains configured provider removal/reconciliation authority; old credentials must not escape cleanup after a flag-off restart.

The backend allocates a random connection UUID per admission. It maps this opaque ID to the authenticated user/session privately; the SFU token/roster contains no application user ID, name, email, role or profile attributes. The JWT names exactly the server-derived room and connection, expires after 60 seconds for initial admission, and grants only room join, subscribe and camera/microphone/screen_share publication. Screen-share audio, data publication, metadata mutation, room create/list/admin/record and ingress admin grants are excluded. All current authorized room-member roles receive these basic media capabilities; this phase adds no persistent per-source permission editor. `MediaAuthority.enforcement.scopedGrants` expresses this actual security capability independently from client quality policy.

The server-side adapter also supports subscribe-only and source-restricted credentials for contract/hostile tests and future backend policies. Their grants are enforced by the real SFU even when a test client overwrites the SDK's local permission preflight. Credentials stay in browser memory and are never put in localStorage/sessionStorage/IndexedDB. Initial room/identity query-string modifications cannot override signed grants.

## Leases, removal and replay

A distinct connection lease lasts 30 seconds and renews through authenticated HTTPS every 10 seconds. Each logical session may allocate four active connections. A two-second server sweep rechecks the current session/membership/block policy without relying on cooperating clients; invalid or stale connections are removed through the server API. Another session cannot renew or leave a lease, even for the same account. Leave retires only that connection ID. Removed membership never silently returns through a renewal; deliberate normal room joining is required if access is still allowed.

The LiveKit adapter reconciles every provider room in its isolated namespace against the live application lease inventory every sweep. Unknown, retired and orphaned identities are removed, including copied tokens replayed after an API restart. It consults the live lease map after network IO so a newly admitted tab is not evicted by an old array snapshot. Providers without inventory reconciliation use 15-minute removal tombstones, extended whenever replay is observed; provider errors retain them and retry. Healthy removal typically takes the two-second interval plus dependency/network time. A replay can briefly connect/forward before removal: this is not cryptographic revocation or a promise of zero-frame leakage.

LiveKit refreshes reconnect credentials; JWT expiry alone does not terminate an active connection. Self-hosted RemoveParticipant does not invalidate a copied token. LiveKit Cloud supports token revocation on supported removal/permission operations, unlike this local self-hosted deployment. Clock tolerance also means the advertised expiry is not a tested exact wall-clock cutoff; the hostile test uses a token expired beyond normal clock tolerance. The completion pass explicitly accepts accurate, supported removal with documented bounds instead of impossible self-hosted guarantees.

The accepted architecture runs one authority/API process per media namespace. It clears its ephemeral SFU rooms on startup, so lost process-local leases cannot leave unmanaged sessions after an API restart. Development uses `study-`, the isolated browser API `test-study-`, its disabled-authority regression `disabled-test-study-`, and hostile probes `probe-study-`; tests cannot reset development rooms. Do not share a namespace between independent authority processes. No durable media state/migration is introduced.

During API downtime, suspended browser timers or provider/admin/network failure, removal is delayed. Existing WebRTC can remain connected during that outage; a hostile cached credential can be retried. Recovery inventory sweeps/startup reset remove known or orphaned sessions, and subsequent replays remain subject to inventory checks. This is best-effort revocation with explicit outage limits, not an outage-proof SFU admission lease. Multi-instance authority, webhook-driven revocation and stronger provider token fencing require later infrastructure design.

## Room-local privacy and blocks

The product UI does not treat the raw SFU roster as social presence. The authenticated `rtc.audience` projection resolves only currently publishing, valid server-owned leases, checks the viewer's current room access, and returns the minimum connection/user/display-name mapping. Unknown provider identities and receive-only connections have no application identity mapping. All camera, screen-tile and audio rendering passes through this projection; unknown/stale media is unsubscribed and removed. Directory polling is two seconds and clears remote projection on failure.

Owner-authorized narrow interpretation: deliberately activating room media makes that publisher visible to authorized people inside that room, including when global current-room/online presence is hidden. The rail labels such entries `Media active`; it does not forge a global Online/study status. Names come from the backend Identity directory. Stopping the last publication removes the media-only entry, leaving any independently authorized ordinary presence intact. Global Friends presence/privacy behavior remains unchanged. Provider participants can observe opaque connection/track metadata needed for RTC, but no private application roster/profile metadata is sent through SFU attributes.

Phase 06 uses a conservative server-side block policy: blocked accounts cannot hold concurrent room-media leases. Conflicting admission is denied. A new block invalidates affected current leases; the sweep removes them. This may stop both affected accounts' media even when only one blocked the other. They retain durable room membership and unrelated users' media is unaffected. When two ordinary blocked members are in a room, the first independently admitted media connection prevents the other's media admission until it leaves. Owner blocks additionally deny room access under the accepted Rooms policy. This deliberately avoids relying on client-hidden media as the block security control; finer-grained mutually isolated subscription groups are deferred. Polling/removal has the transient window described above.

## Capture, rendering and subscription lifecycle

Room entry starts asynchronous receive-only admission, never capture or a pre-entry preview. Explicit microphone/camera activation requests the device; denied/cancelled permissions show an error and retry only on another deliberate action. Refresh and navigation do not retain tokens or reactivate capture. Provider connect/publish/unpublish/mute/device-switch/disconnect are behind the generic contract. Temporary media or signal reconnect updates UI and resumes through the SDK. Terminal disconnect, lease failure, navigation and late async capture cleanup stop browser tracks, clear streams/subscriptions and release references. Device-ended events remove publication and stale live UI. Physical unplug/Bluetooth/sleep/wake are not claimed as hardware-tested.

Standard microphone requests normal echo cancellation/noise suppression/AGC and 64 kbit/s Opus; basic High requests 96 kbit/s with reduced processing and echo cancellation retained. There is no lossless/high-resolution claim or Studio Voice. Camera requests 1280×720@30 with 2 Mbit/s main encoding and a 640×360/400 kbit/s simulcast layer. Browser screen share requests 1920×1080@30 and 4 Mbit/s, no system audio. The normal native getDisplayMedia picker remains mandatory in product code. If admission is not connected, the first Share action connects and asks for a second deliberate click, preserving picker activation; cancellation never loops. Browser-ended share removes its generic workspace tile.

One map owns one HTML media element per logical track. Expansion moves that same node into the generic workspace host while the participant circle becomes an avatar. Closing/minimizing returns it. Multiple device cameras have distinct logical tracks; the rail displays one primary camera and the participant menu can expand each device separately. Unused secondary cameras remain unsubscribed. Multiple screen shares have independent ephemeral tiles and never enter persisted layouts. Screen video uses contain/letterboxing; circle cameras use a circular crop.

Remote circle requests use low/640×360; expanded cameras request up to 720p and screen tiles up to 1080p. Hidden/minimized video unsubscribes. Tests prove a received low-resolution synthetic camera, single renderer identity, and lifecycle; they do not claim an exhaustive simulcast bandwidth benchmark.

Requested versus actual profiles are separate. Three-second RTC stats samples record available actual dimensions, FPS, codec and byte-delta bitrate; unavailable values remain unknown. Bitrates are measured RTP byte rates, not guaranteed total wire cost. Server Prometheus counters can monitor aggregate resource use without media contents. These caps are capture/encoder requests in the trusted product client, not hostile-RTP police: stock LiveKit does not enforce arbitrary dimension/FPS/bitrate guarantees. No transcode/payload inspection enforcement is claimed. High-rate abuse alarms/removal automation and hard media policing are later infrastructure work under the owner's amendment.

## Validation boundaries

Actual local SFU browser tests use different authenticated application users and real PostgreSQL membership/session state. Synthetic canvas/Web Audio replaces physical capture; the production LiveKit adapter, HTTPS admission, WSS, WebRTC/SFU forwarding, remote media elements and room shell are real. The native screen picker result is explicitly substituted; screen-source signaling and forwarding are real. Hostile probes use a deliberately modified real SDK client and real signed restricted/expired/tampered credentials. Mock-provider/SDK tests remain separate for deterministic failure/device races and presentation regression.

Screenshots and validation logs are recorded in the Phase 06 report. No physical devices, Safari/Firefox, real mobile browsers, internet NAT, external TURN/TLS, audio fidelity or hosted CI run are claimed. No Phase 07 quality panel/custom FPS/4K/high-refresh/codec chooser/manual bitrate/Studio Voice/OBS work is included.
