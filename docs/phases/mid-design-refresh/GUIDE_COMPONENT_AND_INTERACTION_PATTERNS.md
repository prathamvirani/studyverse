# Guide — Components & Interaction Patterns

## Integrated Search

Use one field with:

- search icon
- clear
- optional submit icon
- inline loading

Do not stack a separate Search button below.

## Segmented Control

Use for small mutually exclusive mode sets:

- Personal / Shared
- Room / Personal
- Focus / Short Break / Long Break
- selected appearance modes where appropriate

Use animated sliding highlight.

## Select / Combobox

Use branded accessible controls for larger option sets.

Requirements:

- keyboard navigation
- focus states
- selected marker
- mobile-safe popover/sheet behavior
- typeahead/search where useful

## Visual option cards

Prefer for choices where preview matters:

- timer style
- clock style
- privacy when explanation matters
- layout mode
- theme previews
- backgrounds

## Icon buttons

Use for:

- mic
- camera
- share
- play/pause
- stop
- delete-on-hover
- More

Always provide accessible labels/tooltips.

## Settings sheets

Use a real settings surface with categories.

Avoid raw long scroll stacks mixing every subsystem.

## Immediate save

Use for ordinary preferences.

Explicit Save is reserved for:

- named presets
- destructive actions
- multi-step commit flows

## Context menus

Use for low-frequency actions:

- delete
- reorder
- advanced details
- permissions
- reset

## Desktop density

Desktop should not simply enlarge tablet controls.

Use compact spacing while keeping accessible hit targets.

## Touch adaptation

Increase hit areas and spacing at touch-oriented widths.
