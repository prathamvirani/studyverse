# Visual foundation and global shell

MID-01 presentation architecture. Phase 08 remains accepted. This record does not authorize MID-02+, Phase 09, or room lifecycle changes.

## Ownership

`packages/ui/src/styles/tokens.css` owns semantic color, typography, space, shape, depth and motion. `primitives.css` styles the feature-neutral Vue controls in `components/primitives.ts`. They are exported from the existing UI entry point and contain no Nuxt, account, room or provider state. The existing lazy extension hosts and renderer caches are unchanged.

`apps/web/app/app.vue` remains the only global shell. `components/navigation/AppNavigation.vue` consumes its navigation registrations, profile projection and appearance model. One responsive navigation tree becomes a rail above 760px and a bottom bar at/below that width. Profile actions retain the registry's account destination. Home remains `/`; no future `/home` or chat route is introduced.

## Presentation preferences and first paint

`lib/appearance.ts` declares version-1 `app.appearance`, `app.layout-width` and `app.glass-transparency` using the existing `PreferenceDefinition` contract. Choices are `system/light/dark`, `auto/compressed/full`, and `auto` or a manual level from 0–100 in increments of 5. User actions persist through the existing allowlisted IndexedDB adapter and database. No accepted key, database version or migration changes.

The shell owns one `useAppearance` instance. It also writes Secure, SameSite=Lax, path `/`, one-year presentation cookies `study-appearance`, `study-layout-width` and `study-glass-transparency`, each containing only a version and a bounded validated presentation value. These tiny SSR mirrors travel to the same-origin server; they contain no account identity, private history or credentials. They are presentation hints, never authority. No localStorage/sessionStorage adapter or CSP exception is added.

SSR validates the mirror and writes `data-appearance`, `data-layout-width` and `data-glass-transparency` before CSS paints. Missing, corrupt, extra-field or unsupported-version values use System/Auto/Auto. CSS resolves System directly with `prefers-color-scheme`, so OS changes work before and after hydration without JavaScript repaint races. IndexedDB is opened lazily after a preference change, preserving storage-free initial visits. Async IndexedDB reads never override the initial CSS theme. If a cookie is removed/expired while the IndexedDB record remains, System/Auto wins until the next explicit choice. This is a deliberate first-paint policy, not cross-device sync. Storage failures show a local persistence limitation.

Glass defaults to Auto. A native labelled range control previews manual changes on input and persists them through the same adapter/mirror policy. The shared material tokens use a bounded mix: manual Light base opacity 94-58%, elevated 97-68%; Dark base 92-54%, elevated 96-64%. The midpoint is Light 76%/82.5% and Dark 73%/80%. Auto base is 84% light / 82% dark, with elevated opacity 90% in both themes. These are readability bounds, not a request for raw zero-alpha glass. Enumerated root-attribute selectors apply every slider step before hydration without inline styles or CSP exceptions. Reduced transparency and increased contrast override both modes with solid materials. The opaque route surface uses `--canvas`, independently of glass. Future background-specific room adaptation remains MID-04.

Room chrome currently receives deliberate dark compatibility tokens through `.room-shell`, independently of the page appearance. Background artwork is unchanged. The prior room material alpha mapping is preserved independently of the wider global range. Background-aware room opacity, full room theme adoption and feature select conversion belong to later authorized phases.

## Motion and room ownership

The shell keys `NuxtPage` by the router's actual path, disables KeepAlive and page-tree transitions, and renders a separate veil. Old pages are disposed before the new host mounts. No route animation retains a second active room/media tree. Query/hash-only changes and local controls do not trigger the veil.

`onCriticalPageMounted` wraps existing first-frame reads on Home, Account, Friends, Invite, Create Room, Room Details and shared RoomListing. It tracks completion without modifying requests, errors, permissions or response interpretation. A full-viewport canvas cover fades in for 150ms and becomes fully opaque before the guard permits destination mounting. Pending main content is hidden and inert; navigation/footer are hidden behind the cover. Only a centered spinner is visible, with a screen-reader loading label. Escape cancels navigation and returns to the route from which this sequence started.

Nuxt `page:finish`, completion of the critical reads, a Vue DOM flush, first-viewport native image decoding and `document.fonts.ready` gate reveal. The frame helper promotes only above-fold lazy images; offscreen content, video, iframe and provider playback are not readiness gates. Native image failures settle to the page fallback, and existing request errors become the destination's feedback. Once ready, the cover fades out for 200ms and its completed loading status is hidden from the accessibility tree. Entry restores loading semantics. Ordinary routes have no translation, scaling or clip-path motion. The canvas material is fully opaque and cover opacity remains 1 throughout loading; fades run only before mounting and after readiness; no partially assembled destination is exposed, no timed minimum is added after readiness, and no old room/media subtree is retained for animation.

Each route attempt owns a generation and an abortable frame preparation. Retired reads, readiness completions, cancelled guards and duplicate-navigation failures cannot uncover or clear a newer attempt. Router failures belonging to the current attempt clear it. Page completion focuses main after it becomes usable. Query/hash-only changes and local controls do not trigger route motion. Room entry retains the accepted explicit POST join inside the details route.

Ordinary route changes use only short fades. Surface opening/closing, profile origin, navigation lift/press and spring-like segmented movement retain their spatial motion. Shared timings are micro 140ms, quick 200ms, standard 320ms and expressive 480ms. Native dialog discrete display/overlay transitions preserve its top layer during closing where supported; older browsers fall back to immediate native closing. OS/browser `prefers-reduced-motion` removes travel/rotation and transition duration as an accessibility override. There is no separate product Reduce Motion setting. Accepted workspace dragging/snapping and room animations are unchanged; this record does not authorize a room redesign.

## Adoption contracts

- `IntegratedSearch`: controlled value; caller owns query, pagination and errors; Enter/optional trailing submit; labelled clear, inline busy, disabled and described error states; unique Vue IDs.
- `StudySelect`: controlled selection; trigger retains focus with combobox/listbox semantics; arrows, Home/End, Escape, Tab and typeahead; selected marker and disabled options. The bounded option list expands in flow, avoiding viewport/sheet clipping. Searchable/custom-entry comboboxes wait for a real consumer.
- `SegmentedControl`: controlled radiogroup, roving Tab stop, arrows/Home/End, disabled options, CSS sliding highlight. Dynamic sizing is applied through CSSOM after mount so the strict CSP does not need to allow SSR style attributes.
- `SettingsSheet`: controlled native modal dialog; browser top layer and inert background; Escape/outside dismissal, explicit Tab boundary wrapping and opener restoration. Optional category slot; no domain draft/save state. Nonmodal profile actions use the native auto popover.
- `GlassSurface`, `PageHeader`, `ContextPane`, `IconButton`, `StatusBadge`, `Loader`: feature-neutral material, layout, accessible action, text status and loading contracts. ContextPane is available for subsequent page composition; MID-01 does not invent sidebar content.

Font files are self-hosted through pinned Fontsource packages: Inter Variable for UI and Instrument Serif 400 normal/italic for selected display moments. Unicode subsets load on demand, with `font-display: swap`. Lucide supplies tree-shaken SVG icons. Redistribution notices ship under `apps/web/public/licenses/`. No Apple font files or remote font service are used.

MID-08 keeps these families and existing theme/glass owners. Nuxt's `@nuxt/fonts` module generates faces/fallbacks from the build-only `infra/nuxt/local-font-provider.ts`: pinned Fontsource CSS is read locally, its Unicode ranges are retained, and content-hashed WOFF2 assets are served from `/fonts` with one-year caching. Remote font providers and eager subset preloads are disabled. Shared token CSS no longer imports font files implicitly; standalone UI consumers can import `@study/ui/styles/fonts.css` explicitly.

Five Lucide icons are bundled by `@nuxt/icon` for primary navigation and favorite stars, with external API fallback disabled. Existing shared SVG controls stay compatible. `@nuxt/image` uses local IPX for public curated thumbnails and canonical `i.ytimg.com` metadata thumbnails. Full selected-room scenes, custom object URLs and private assets retain their existing preparation/authorization path. Critical-frame readiness still waits for native image decoding and fonts; module components do not bypass this contract.
